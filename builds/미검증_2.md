## 구현 내용

### 활동 코인

- `HUSBANDRY` 활동을 추가했다.
- 소, 돼지, 양, 닭 등 `Animals` 번식 시 `BREED` 보상을 지급한다.
- 플레이어가 수동적 동물을 직접 처치하면 `SLAUGHTER` 보상을 지급한다.
- RPG 태그가 붙은 대상은 사육 보상에서 제외한다.
- 자연 수동적 동물은 RPG 후보 판정에서 제외하여 `rpg_mob` 태그를 붙이지 않는다.
- 낚시는 결과물을 `FISH`, `TREASURE`, `JUNK`로 분류하고 등급별 보상을 사용한다.
- 커스텀 RPG 몬스터의 코인은 기존 `MobRewardService`의 몬스터별 `coinReward`만 사용한다. 일반 사냥 활동 코인을 함께 지급하지 않아 중복 지급을 방지한다.

### 설정 키

`progression-loop.yml`의 다음 경로에서 수정한다.

```yaml
activity-coins:
  activities:
    FISHING:
      tiers:
        FISH: { enabled: true, coins: 10 }
        TREASURE: { enabled: true, coins: 35 }
        JUNK: { enabled: true, coins: 3 }
    HUSBANDRY:
      tiers:
        BREED: { enabled: true, coins: 12 }
        SLAUGHTER: { enabled: true, coins: 6 }
```

부모 활동의 `enabled`, `allowed-worlds`, `cooldown-ticks`도 공통 적용된다.

### 자동 퀘스트

- `/quest` 및 기존 `/rpgquest` 경로에 자동 퀘스트 처리를 연결했다.
- `HUNT`, `ITEM_DELIVERY` 두 종류를 지원한다.
- 활성 퀘스트 수, 목표량, 시간 제한, 보상, 수락·완료·실패·포기 대기시간을 YAML로 조정한다.
- 아이템 납품은 이름이나 Material이 아니라 커스텀 아이템 PDC ID로 수량을 확인한다.
- 납품 완료 시 요구 수량만 차감한다.
- 퀘스트 진행과 보상은 플레이어별 데이터에 저장한다.
- 서버 재시작 후 자동 퀘스트, 진행도, 만료 시각, 대기시간을 복원한다.
- 메인 메뉴의 퀘스트 슬롯에서 자동 퀘스트와 기존 정적 퀘스트를 함께 확인할 수 있다.
- 퀘스트 항목에서 완료 또는 포기할 수 있다.

`quests.yml`의 `auto` 섹션:

```yaml
auto:
  max-active: 2
  types: [HUNT, ITEM_DELIVERY]
  time-limit-seconds: 1800
  cooldown:
    after-accept-seconds: 300
    after-complete-seconds: 60
    after-fail-seconds: 300
    after-abandon-seconds: 300
  rewards:
    coins: 25
    base-exp: 20
```

### UI 도움말

- 플레이어 입장 시 ActionBar에 `Shift + F: 메뉴 열기 | 퀘스트 확인` 안내를 보낸다.
- Shift + F 입력 시 기존 메인 메뉴를 연다.
- 메인 메뉴의 퀘스트 항목에서 새 자동 퀘스트에 접근할 수 있다.

### 저장 및 마이그레이션

- 플레이어 데이터 schema를 3으로 올렸다.
- 자동 퀘스트는 `quests.cooldown-until`, `quests.active.slot-*`에 저장한다.
- 기존 정적 퀘스트 데이터는 유지한다.
- 설정 마이그레이션 시 `progression-loop.yml`의 사육·낚시 등급 설정과 `quests.yml`의 `auto` 기본값을 보완한다.

## 미검증 위험

- Paper 이벤트가 서버 버전에 따라 번식·낚시 결과를 다르게 전달할 수 있다.
- 자연 동물의 범위는 현재 `Animals`와 명시적 RPG 후보 제외 목록에 의존하므로 신규 동물 추가 시 목록 점검이 필요하다.
- 서버 플레이 테스트가 없어 실제 코인 중복, 데이터 저장, GUI 입력 처리까지는 확정할 수 없다.
- 기존 레거시 퀘스트와 새 자동 퀘스트가 같은 플레이어 데이터 파일을 사용하므로 첫 적용 전 백업이 필요하다.
