HyunseoRPG 탐험 구현/설계 대응 및 누락·테스트 정리본
작성일: 2026-08-19

요약
현재 GitHub 기준 상태는 “탐험 E1~E8 엔진/계약 + 제한 프로토타입 일부 구현, 영지는 아직 설계 범위”로 보는 것이 맞다.
즉, 코드 쪽으로는 탐험 모듈의 뼈대, 구조물 Registry, 구조물 감지 계약, 런타임, 이벤트 컴포넌트 계약, 상태 기록, objective 추적 골격이 들어가 있다.
반면 설계 문서에 있는 실제 구조물별 콘텐츠, 퍼즐, 보상, 커스텀 몹, 연출, 영지 연계는 대부분 아직 구현되지 않았거나 live test required 상태로 분리해야 한다.

2. 구조물 / 콘텐츠 단위 대응

2-1. 주요 구조물 콘텐츠 대응표

구조물 / 콘텐츠 단위: 마녀 오두막
- 설계상 콘텐츠: 상징 3개 입력 → 가마솥 연출 → 수렁 주술사 전투 → 보상 지점 개방
- 현재 구현: swamp_hut 정의, vanilla:witch 1마리 scripted spawn 프로토타입
- 판정: 부분 구현. 실제 수렁 주술사, 상징 퍼즐, 보상은 미구현.

구조물 / 콘텐츠 단위: 약탈자 전초기지
- 설계상 콘텐츠: 내부 진입 또는 핵심 상자 트리거 → 깃발 연출 → 외곽 병력 접근 → 균열 사수 합류 → 보상
- 현재 구현: pillager_outpost 정의, vanilla:pillager 2마리 scout wave 프로토타입
- 판정: 부분 구현. 깃발, 균열 사수, 루팅 트리거, 보상은 미구현.

구조물 / 콘텐츠 단위: 사막 피라미드
- 설계상 콘텐츠: 퍼즐 상자, 시한폭탄, 아재개그 퀴즈 Variant, 입구 임시 봉쇄, 지하 보물방
- 현재 구현: desert_pyramid 구조물 항목만 있음, variant 없음
- 판정: 콘텐츠 미구현.

구조물 / 콘텐츠 단위: 바다 신전
- 설계상 콘텐츠: 3봉인, 경고, 상층 전투장 이동, 심해의 파도술사, 수중 병력, 봉인 연출
- 현재 구현: ocean_monument 항목만 있음, variant 없음
- 판정: 콘텐츠 미구현.

구조물 / 콘텐츠 단위: 난파선
- 설계상 콘텐츠: RPG 난파선 접근 시 급류 드라운드 계열 이벤트 후보
- 현재 구현: shipwreck 항목만 있음, variant 없음
- 판정: 설계 후보 / 미구현.

구조물 / 콘텐츠 단위: 시련의 회당
- 설계상 콘텐츠: 짧은 열쇠 맞추기, 성공 시 RPG 보상 추가 가능
- 현재 구현: trial_chambers 항목만 있음, variant 없음
- 판정: 콘텐츠 미구현.

구조물 / 콘텐츠 단위: 네더 요새
- 설계상 콘텐츠: 구조 변화 없이 커스텀 네더 몹 스폰 중심
- 현재 구현: nether_fortress 항목만 있음, variant 없음
- 판정: 콘텐츠 미구현.

구조물 / 콘텐츠 단위: 보루 잔해

구조물 / 콘텐츠 단위: 엔드 도시

- 현재 구현: end_city 항목만 있음, variant 없음

구조물 / 콘텐츠 단위: 엔드 함선

구조물 / 콘텐츠 단위: 삼림 대저택

6. 이후 작업 순서 정리

현재 합의된 작업 방식
- 작업 단위마다 브랜치를 분리한다.
- 브랜치마다 코드 변경과 함께 누락 보고서 / 구현 보류 항목 / live test required 항목을 같이 남긴다.
- 프롬프트별 구현은 진행하되, 작업 환경상 구현할 수 없거나 의도적으로 누락한 부분은 반드시 보고서에 남긴다.
- E2 이후 구현에서는 E1 충돌이나 오류 발생 체크와 수정까지 포함한다.
- 실제 GitHub 작업에서는 모든 브랜치를 한 번에 통합하지 않아도 된다. 필요한 부분만 선별해서 오류 수정 브랜치를 새로 만들고, 테스트와 검증을 반복한다.

검증 / 구현 순서
1. 최신 탐험 브랜치 기준으로 정적 검증을 수행한다.
2. E1~E8 또는 이후 브랜치 단위 변경이 최신 기준에서 충돌하지 않는지 확인한다.
3. live test required 항목을 별도 목록으로 유지한다.
4. 제한 프로토타입 콘텐츠를 먼저 라이브 테스트한다.
5. content_missing을 제외한 엔진 / 구조 / 런타임 / persistence / cleanup 항목을 먼저 검증한다.
6. 위 항목이 통과하면 구조물별 실제 콘텐츠를 구현한다.
7. 실제 콘텐츠 구현 후 구조물 단위 live test를 수행한다.
8. 오류 발생 시 legacy branch, error-detected branch, fix branch, 최신 branch를 대조해 원인을 특정한다.
9. 필요한 경우 legacy branch의 일부 소스만 선별 반영하거나 별도 fix branch에서 수정한다.
10. 검증 통과 후 최신 브랜치에 반영하고 main 반영 대상으로 둔다.

브랜치 해석
- error-detected: Codex 작업 중 발생한 오류 수정본
- fix/alchemy...: 이후 후속 오류 처리 작업 포함
- exploration 관련 브랜치: 시간순으로 패키지 → 다음 프롬프트 → 그 다음 프롬프트 흐름
- 최신 탐험 기준: 최신 branch 우선 적용
- legacy branch: live test 중 오류가 발생했을 때 원인 특정용 참조 자료. 필요 시 일부 코드 선별 이식 가능.


7. 최종 결론

현재 구현된 쪽은 탐험 엔진, 구조물 런타임, 이벤트 계약, 상태 기록, 제한 프로토타입이다.
설계상 실제 콘텐츠 쪽은 오두막, 전초기지, 피라미드, 바다 신전이 1차 주요 구현 대상이고, 난파선, 시련의 회당, 네더 요새, 보루 잔해, 엔드 도시는 후속 구현 대상으로 분리된다.
정글 사원, 엔드 포탈 요새, 흔적 폐허, 해저 폐허, 네더 화석은 의도적 배제 또는 바닐라 유지로 봐야 한다.
영지는 설계 문서상 존재하지만 현재 기준에서는 탐험 이후 별도 스코프이며, 영지까지 확장할 경우 T1~T9 전체 구현과 탐험 연계 검증을 별도 단계로 분리해야 한다.

따라서 현재 단계에서 보고해야 할 핵심은 다음 세 가지다.
1. 구현됨: 탐험 엔진 / 계약 / 구조물 런타임 / 제한 프로토타입
2. 미구현: 구조물별 실제 콘텐츠 / 보상 / 퍼즐 / 커스텀 몹 / 연출 / 영지
3. 검증 필요: 정적 빌드·테스트, live server 구조물 감지·activation·cleanup·persistence, 콘텐츠 구현 후 구조물별 live test
